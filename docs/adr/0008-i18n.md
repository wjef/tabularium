# 0008 — Internationalization from day one

Date: 2026-10-17 · Status: Accepted; amended 2026-10-20 (see below)

## Context
UI is English for now; other languages (e.g. Polish) should be switchable later.
Retrofitting translation onto hard-coded strings is tedious.

## Decision
- All UI strings go through gettext (`_()` in Python, `{% trans %}` / `_()` in Jinja2 via
  `jinja2.ext.i18n`). Babel extracts them (`babel.cfg`) into `src/tabularium/locales/`.
- Language selected by `[ui] language` in config (default `en`); a UI switch comes later.
- User data (tag and entity names) is never translated.

## Consequences
- Adding a language = add a `.po` file and compile it; no code changes.

## Amendment (2026-10-20, with [0010](0010-single-page-front-end.md))
The Jinja2 templates are gone. Backend messages shown to the user (domain errors, results) stay
marked with `N_()` and extracted by Babel. The React interface has plain English strings for
now; when Polish is added, the frontend gets its own message catalog (library to be chosen
then) and the same `[ui] language` setting, so the decision "English now, Polish later" holds.
